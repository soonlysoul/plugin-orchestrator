# Journal des versions

Format inspiré de [Keep a Changelog](https://keepachangelog.com/fr/1.1.0/) ; versionnage [SemVer](https://semver.org/lang/fr/) : correctif pour une consigne corrigée, mineure pour un composant ajouté, majeure pour un changement qui casse l'existant.

## [0.1.0] — en cours

### Ajouté

- Skill `recover-session` (US-6) : reprendre un travail interrompu dans un projet `.forge/` depuis ce qui est sur disque — `.forge/checkpoint.md`, l'historique Git, l'état du dépôt — sans rien changer avant l'accord de l'utilisateur : checkpoint relu et comparé à `HEAD`, à la branche et à `git status`, incohérences signalées (commits plus récents que `last_commit` hors celui qui porte le checkpoint, autre branche, fichiers suivis modifiés non consignés, étape cochée sans commande), seule la commande consignée dans la table des tests relancée, telle quelle et quel que soit le langage de la partie (jamais la suite complète ni une commande qui change le projet, rien sur une autre branche), résultat comparé au consigné (un ROUGE attendu est l'état normal), résumé en dix lignes au plus et question avant de reprendre ; un commit plus récent qui semble tenir l'étape suivante est dit, jamais coché. Généralisé depuis plugin-flutter, dé-Flutterisé ; évalué VERT avec témoin (deux demandes qui déclenchent, une question Git qui ne déclenche pas).
- Skill `git-workflow` (US-4) : brancher, stager, committer, inspecter les diffs et pousser de façon sûre dans un projet `.forge/`, mono ou multi-parties, le dépôt étant la racine du projet — classes d'actions (libre, confirmation, préautorisation, accord explicite, interdit par guard-destructive), branche `<préfixe>/<AC>-<slug>` depuis `project.branch_prefix` à partir de la branche par défaut, question avant d'emporter un fichier suivi modifié (jamais de stash silencieux), staging explicite avec les manifestes de la `toolchain` et relecture de l'index pour les secrets, Conventional Commits atomiques, commit qui emporte le checkpoint, push d'une branche de travail seulement si préautorisé ou demandé, jamais la branche par défaut, dont le push revient à l'utilisateur. Repris de plugin-flutter ; évalué VERT avec témoin (deux demandes qui déclenchent, une qui ne déclenche pas).
- Agent `product-architect` (US-2) : une tâche produit bornée — `docs/product/PRD.md` rédigé depuis une description du besoin ou reconstruit depuis le code d'un projet existant, critères d'acceptation AC-xxx numérotés, testables, jamais renumérotés ; questions d'architecture, de dépendances, de plateformes ou de découpage en OPEN_QUESTIONS vers l'architecte du plugin de la partie ; rapport au contrat de délégation (ACCEPTANCE_CRITERIA, INTERFACE: 1). Outils Read, Grep, Glob, Write, Edit ; écrit sous `docs/product/` seulement, sans shell, portée déclarée dans `hooks/agent-scope.json`. Généralisé depuis plugin-flutter, dé-Flutterisé.
- Hook `doc-status-guard` (US-13) : PostToolUse sur Edit et Write, fail-open, inerte hors d'un document projet (`.md` sous un `docs/` d'un projet `.forge/`, racine ou partie) portant la ligne `| Status | … |` — un document APPROVED dont le corps ne correspond plus à l'empreinte consignée à son approbation dans `.forge/approvals.log` repasse en REVIEW, la ligne Approved gardant la date perdue, et Claude en est prévenu ; un APPROVED sans trace au journal repasse en REVIEW à sa première modification. Repris de plugin-plugin, avec la bibliothèque `scripts/lib/doc-status.sh` (statut, empreinte, journal des approbations) partagée avec le futur `scripts/orch.sh approve` ; message en français.
- Hook `agent-scope-guard` (US-2, US-8, US-10) : PreToolUse sur Edit, Write, NotebookEdit, Bash, PowerShell et Monitor, fail-closed, inerte hors des agents de ce plugin (`agent_type` à préfixe `plugin-orchestrator:` ; les agents d'un autre plugin sont ignorés, même à nom égal) — tient chaque agent aux dossiers d'écriture et à la liste blanche de commandes simples que `hooks/agent-scope.json` déclare pour lui, écrite par `pp.sh add-agent` à son ajout ; entrées de commande comparées mot à mot comme préfixe ; commandes composées, redirections, substitutions, affectations en tête, options `--output`/`--write` et chemins avec `.` ou `..` refusés quelle que soit la liste. Généralisé depuis plugin-flutter, portées au modèle plugin-plugin ; raisons en français.
- Hook `checkpoint-reminder` (US-6, US-13) : Stop, fail-open, inerte sans `.forge/checkpoint.md` ou si `stop_hook_active` — quand le checkpoint est plus vieux que le dernier commit ou qu'un changement non commité du projet, rappel unique de le mettre à jour puis de s'arrêter ; un dernier commit qui porte le checkpoint, inchangé depuis, ne compte pas. Repris tel quel de plugin-flutter ; message en français.
- Hook `protect-sensitive` (US-13) : PreToolUse sur Edit, Write et NotebookEdit, fail-closed, inerte hors d'un projet `.forge/` — demande confirmation avant d'écrire du matériel de signature (`key.properties`, `*.keystore`, `*.jks`, `*.p12`, `*.pfx`), des entitlements Apple, du code de CI (`.github/workflows/*`, `.github/actions/*`) ou `.forge/config.yaml`, protégé partout. Repris tel quel de plugin-flutter ; raison en français.
- Hook `secret-scan` (US-13) : PreToolUse sur Bash, PowerShell et Monitor, fail-closed, inerte sans le mot `commit` — avant un `git commit`, refuse les noms de fichiers secrets et les motifs de secret dans les lignes que le commit peut ajouter (index, `-a`, chemins, `git add` sur la même ligne), gitleaks s'il est installé, sans jamais afficher un secret. Repris de plugin-flutter ; raisons en français ; jetons npm et PyPI, fichiers `.pypirc` et `.netrc` ajoutés.
- Hook `guard-destructive` (US-13) : PreToolUse sur Bash, PowerShell et Monitor, fail-closed, toujours actif — git qui jette du travail ou réécrit le distant, suppression récursive forcée hors de `build/`, `gh` qui supprime, fusionne ou publie, publication vers pub.dev, npm ou PyPI sans `--dry-run`. Repris de plugin-flutter avec le lexer partagé `hooks/scripts/lib/shell-lexer.sh` ; raisons en français ; registres npm et PyPI ajoutés.
- Charpente posée par plugin-plugin le 2026-10-23 : manifeste, marketplace locale, licence, documents et suite de tests `tests/run-all.sh`.
